按查询负载评估维度过滤贡献度

本文档为 filter_contribution.md 的 HTML 图示版， 用 16×16 矩阵展示块 c 在 (d₁,d₂) 上的查询区域。Markdown 版中的 ASCII 示意图见原文章节 2–4。

1. 重叠比例 ρ（启发式，对应 Markdown 第 3 节）

对 border 块 c、维 d、查询 q ∈ Qc，将查询裁剪到块内区间 I(q,c,d) 后：

ρ(q,c,d) = |I(q,c,d)| / ℓc(d)   （ℓc 为块在该维上的点数，本例为 16）
  • ρ 越大：查询在该维块内越宽 → 该维对过滤器判别力越弱 → 越优先从编码维度中剔除。
  • ρ 越小：存在强选择性查询 → 越应保留该维。

块级平均：ρ̄(c,d) = (1/|Qc|) Σq∈Qc ρ(q,c,d)，用于对维度排序。

2. 例子设定（对应 Markdown 第 4.1 节）

  • 块 c 在 d₁、d₂ 上取值均为 [0,15]，故平面区域为 16×16 个点（下图每一格 = 一个整数坐标 (d₁,d₂)）。
  • q₁：d₁ ∈ [0,14]，d₂ ∈ [0,15]（在 d₂ 方向拉满，d₁ 缺右端点 15）。
  • q₂：d₁ ∈ [0,14]，d₂ ∈ [0,1]（在 d₁ 上与 q₁ 同宽，在 d₂ 上仅为底部窄条）。
  • Qc = {q₁, q₂}（两条查询均使该块为 border 且走过滤器）。

3.1 从图上读 d₁ / d₂ 的差异

  • d₁ 方向：q₁、q₂ 的着色列范围相同（均为列 0–14），两条查询在 d₁ 上都「几乎铺满」块宽 → 该维选择性弱。

4. 逐维 ρ 与 ρ̄（对应 Markdown 第 4.2–4.3 节）

查询 I(q,c,d₁) ρ(q,c,d₁) I(q,c,d₂) ρ(q,c,d₂)
q₁ [0,14]，长 15 15/16 [0,15]，长 16 1
q₂ [0,14]，长 15 15/16 [0,1]，长 2 2/16 = 1/8
ρ̄(c,d₁) = (15/16 + 15/16) / 2 = 15/16 ≈ 0.94
ρ̄(c,d₂) = (1 + 1/8) / 2 = 9/16 ≈ 0.56
结论：因 ρ̄(c,d₁) > ρ̄(c,d₂)，d₁ 更适合优先从块 c 的过滤器编码维度中剔除； 若先删 d₂，q₂ 在 d₂ 上的窄区间 [0,1] 无法再参与多维范围 ID 的区分，FPR 更可能明显上升。 另：ρmin(c,d₂)=1/8 也提示 d₂ 不宜草率删除（见 Markdown 第 6 节）。

5. 与极端满覆盖情形的对照（Markdown 第 2 节）

在 d₁ 上，两条查询都缺 d₁=15 一点，ρ=15/16，接近「满覆盖」极端：删 d₁ 主要增加假阳性，一般不引入假阴性（在投影语义正确时）。 在 d₂ 上，q₁ 满覆盖而 q₂ 极窄，不能 用「平均很宽」忽视 q₂——这正是引入 ρ̄ 与 ρmin 的原因。
